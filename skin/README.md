# 中英双打羊皮纸

适合同时有中英文混打输入需求的人群。

配色：浅色为羊皮纸护眼底，深色为柔和灰（非纯黑），按键文字均保证高对比。

## 三套键盘，两套 Rime 方案

| 键盘 | Rime 方案 | 用途 |
|---|---|---|
| **26 键中英混打** | `rime_ice` | 中英文同时出候选 |
| **九宫格** | `rime_ice`（同上） | 数字映射并在同一个方案里，5.0 起不再是独立方案 |
| **纯英文** | `melt_eng` | 有词库、有前缀补全，只出单词不连句 |

切换键**同时切键盘和方案**（`combine` 动作），不会出现「键盘换了方案没换」。

## 键位

三套键盘两两直达，都只要点一下：

```
九宫格底行     [，。][En]   空格   [中En]
                 ↑    ↑             ↑ 点按 → 26 键中英混打
               标点  纯英文           上滑 → 中英切换(ascii_mode)

26 键底行     [123][En]  ，  空格  [T9]  enter
                ↑    ↑              ↑ 点按 → 九宫格
             数字  纯英文             上滑 → 中英切换

纯英文底行    [123][T9]  ，  空格  [中En] enter
                     ↑              ↑ 点按 → 26 键中英混打
                   九宫格
```

5.1 新增的是九宫格上的 `[En]`（空格左边劈出来的一小块）和纯英文键盘上的 `[T9]`。
此前从九宫格去纯英文要经 26 键中转，回来也是。

为什么要有直达纯英文的键：中英混打下，一个英文单词如果本身就是合法拼音
（`you`、`he`、`can`、`like`），首位出的是中文，这是混打的固有代价，没法靠配置
消掉。要连着打英文时，切到纯英文键盘最省事。

## 九宫格的中文标点

底行左边那个键就是**中文标点主键**：

| 键 | 手势 | 出什么 |
|---|---|---|
| **标点键**（底行左） | 点按 | `，`（键面主字） |
| | 上划 | `。`（键面上方有小字提示） |
| | 长按 | `、：；“”（）— ~ / _ & # *` |
| **1 键**（`@/.`） | 长按 | `@ ？ ！ … % £ $ ¥ + - × ÷ =` |
| | 下划 | `，` |
| | 上划 | 数字 `1` |
| | 点按 | 走 Rime punctuator（`1 @ . / : _ - #`）；打字时是分词键 |

逗号和句号占了中文标点用量的绝大部分，所以给了点按和上划这两个最快的手势，
一个动作直出，不用长按。其余标点在长按网格里，手指滑到目标松开即可。

数学与货币符号集中在 1 键长按，一字排开，写公式、记账、填金额时不用切数字键盘。

所有这些键都用 `symbol` 动作（直发系统），不经过 Rime 的 punctuator 转换。

## 左侧标点列点完会跳回 26 键？删掉两个符号就好

**现象**：九宫格最左侧那一列，点选标点上屏后，键盘立刻跳回 26 键。

**解法**：在**元书 App 的符号设置**里（就是那一列的内容来源），把 `，` 和 `。`
这两条删掉。删掉之后点其余标点都不再跳。

具体菜单名可能随元书版本变化，找「符号」「常用符号」相关的设置项即可。

**为什么皮肤修不了**：那一列不是皮肤定义的按键，而是元书内置组件：

```jsonnet
t9SymbolsCollection: {
  params: { type: 't9Symbols' },   // 全部内容就这一行，不接受任何参数
}
```

它平时显示标点、打字时切换成拼音候选，行为写在元书 App 内部。皮肤只能声明
这个位置放一个它，连参数都传不了。上游空山素影的定义与此完全一致，
不是本皮肤引入的。

**另外两条走不通的路**（省得你试）：

- **把元书主键盘改成九宫格**：九宫格是不跳了，26 键上轮到跳，方向对调而已。
- **换掉那个组件**：那一列在打字时是拼音候选，换成自定义按键等于砍掉九宫格选音。

即使不删那两个符号，本皮肤的标点键和 1 键也是普通按键，动作只有「上屏一个
符号」，不带切键盘，任何情况下都不会跳。

## 数字键盘上的 @ 点不出 @？

九宫格 → 左下角 `123` → 数字键盘，左上角那列符号里点 `@`，出来的是一串候选
`1 @ ！ ： 、 …… ～` 而不是 `@`。

那一列是元书内置组件 `numericSymbols`，点选后把字符送进 Rime，被方案的
punctuator 拦下了（`"@"` 的值是个列表，列表就是弹候选的意思）。

本仓库的 `src/patches/rime_ice.custom.yaml` 已修：把 `"@"` 的值改成单个字符串，
Rime 见到单字符串就直接上屏。只用皮肤不用本仓库 Rime 配置的话，自己在方案补丁
里加这一行即可：

```yaml
patch:
  "punctuator/half_shape/@": "@"
```

注意要逐键写，不要整块重定义 `punctuator/half_shape` —— 那会把全部中文标点一起
盖掉。行式数字键盘（英文键盘上的那个）的 `@` 键同样用 `symbol`，直发系统。

## 想让九宫格当默认键盘？

`Settings.libsonnet` 里把 `primaryKeyboard` 改成 `'9'`，重新编译即可。

原理：元书调出键盘时打开的类型固定叫 `pinyin`，这个设置决定 `pinyin` 映射到
哪套布局，另一套自动挂到 `pinyin9`。两颗切换键的目标名由派生值跟着换，
不用手动改按键。

顺带一提，这也决定了元书上屏符号后返回哪个键盘 —— 那是 App 的「返回主键盘」
行为，跟本设置是同一个 `pinyin` 类型。

5.0 起九宫格和 26 键共用 `rime_ice` 一个方案，所以不存在「布局和方案对不上」
的问题了（4.x 时两者各用一个方案，元书记方案、皮肤定布局，会错配出一串数字）。

## 呼出键盘就打出英文 / 数字？

**现象**：新开一个 App 呼出键盘，26 键上打出的是英文字母，九宫格上打出的是数字；
切一下键盘再切回来就正常了。

**原因**：雾凇的 `switches` 里 `ascii_mode` 没有 `reset`，状态会跨会话保留。
上次上划切到英文模式没切回来，下次呼出时它还开着 —— `ascii_mode` 为开时按键
原样透传，26 键上是字母，九宫格上是数字。切键盘能治，是因为切换键会
`switchRimeSchema`，重新加载方案时开关被重置。

**修法**：`src/patches/rime_ice.custom.yaml` 已加

```yaml
patch:
  switches/@0/reset: 0    # @0 即 ascii_mode，见 rime_ice.schema.yaml
```

每次加载方案强制回中文模式。临时打英文仍然上划切换，只是不再被带到下一次。

不用本仓库 Rime 配置的话，自己在方案补丁里加这一行即可。

## 数字为什么都用 `symbol` 直发

九宫格是靠数字键打拼音的，所以在方案里**数字就是输入码**。任何键只要用
`character` 把数字送进 Rime，数字就会被当成拼音吃进候选区：

- 数字键盘的 0–9：打 `1989` 四个数字进了候选区，还得点一下才上屏（4.8 修）
- 26 键上滑出数字：上滑 `w` 想要 `2`，出来的是「啊」（5.0 把数字并进方案后
  引入的回归，5.1 修）

所以这两处的数字一律用 `symbol`，绕开 Rime 直接进输入框。

九宫格自己的数字键（`Layout9.libsonnet` 的 `t9OneButton` 等）仍是 `character`，
那是九宫格拼音输入的正路，不能动。等号键也保留 `character`，因为 `=` 是雾凇
计算器的前缀（打 `=1+1` 出结果）。

## 打字时字不在输入框里？开内嵌编辑

默认情况下正在打的字只出现在候选条上，要点一下候选（或按空格）才进输入框。
英文键盘上尤其别扭 —— 明明是在打英文单词，却像在选词。

工具栏新增了「**内嵌**」按钮（代号 `28`），点一下切换**内嵌编辑**：
正在打的字直接显示在输入框里，敲空格确认。

**词库和前缀补全不受影响** —— 内嵌编辑只改显示位置，不改输入流程。
这也是为什么不建议把英文键盘的字母键改成 `symbol`：那样确实直出，但四万多条
词库和 `inter` → `international` 的补全会一起失效。

默认工具栏已包含该按钮。元书 App 侧若有「内嵌编辑」的持久设置，在那里打开可以免去
每次点按。

## 调参

主要开关在 `jsonnet/Settings.libsonnet`：

```jsonnet
dualKeyboard: true,        // 多键盘总开关
primaryKeyboard: '26',     // 主键盘：'26' 或 '9'，决定调出键盘时默认显示哪个
schemaFor9:  'rime_ice',   // 九宫格方案（5.0 起与 26 键同一个）
schemaFor26: 'rime_ice',   // 26 键方案
schemaForEn: 'melt_eng',   // 纯英文方案
accentColor: 6,            // 主题色 0-无 1-红 2-绿 3-橙 4-蓝 5-紫 6-墨印
uppercaseForChinese: true, // 中文模式字母键大写显示
```

按键功能定义在 `jsonnet/Buttons/`。

## 编译

手机端：长按皮肤 → 「运行 main.jsonnet」

PC 端（项目根目录）：
```bash
./build.sh          # debug，YAML 可读
./build.sh release  # 紧凑格式
```
